- Python with pdfplumber for text-based PDF layout and table extraction. Invoke it through a controlled worker process and exchange validated JSON. Keep the application and domain model in TypeScript.
- Playwright with Chromium for PDF reports using dedicated print templates. ExcelJS for actual .xlsx workbooks and spreadsheet ingestion where appropriate.
- Private Cloudflare R2 for production source files and generated exports, through a storage adapter using its S3-compatible API.
- Docker Compose for a dedicated Ubuntu VPS deployment: web application plus worker behind an HTTPS reverse proxy. Production database: managed PostgreSQL on Neon. Local development: ordinary PostgreSQL plus a private filesystem storage adapter, so development does not require paid accounts or production credentials.
- Vitest for domain and calculation checks; PostgreSQL integration checks for persistence, transactions, access, and jobs; Playwright for browser workflows.

Before dependency installation, consult current official documentation and select mutually compatible stable versions. In particular, verify the Prisma/Better Auth adapter combination, Node requirements, and the Playwright package/browser version match. Prefer a documented working combination over the newest major release. Record exact selections and commit lockfiles; do not invent APIs or combine examples from incompatible major versions.

Use a single repository with clear domain, persistence, web, reporting, and worker boundaries. A simple workspace is acceptable. 5. Manpower accounting is a critical requirement

Initially manpower is entered manually, mainly as weekly installer counts. Weekly inputs expand to project-calendar workdays. Allow copying weeks, filling ranges, daily overrides, and explicit timed blocks for partial days or shifts.

Use one canonical resource-capacity model. A workforce pool supplies people for a date/time block; allocations reserve that capacity for phases, areas, systems, activities, and dedicated crews. Nested allocations subdivide existing reservations. They do not create more people. Preserve identity of anonymous resource slices internally where necessary; individual installer names are optional.

Example: eight installers reserved to Phase 1, with three allocated to an electrical room and five to a data hall, still means eight installers. Allocating only three leaves five available within the phase. Do not add parent envelopes to their children. Broad Shared systems labor is not copied into each system total.

A dedicated crew reserves people from the shared workforce for selected dates. Splitting a crew, assigning a system, or returning it to shared work changes allocation, not total headcount. Increasing the workforce must be an explicit action. Reject reservations beyond available capacity and concurrent duplicate bookings of the same resource slice, with a correction path. Sequential assignments within a day are valid.

Leadership is separate from installer pools. Tyler is initially a named PM planned onsite full time, with adjustable dates and onsite days/hours. One named main foreman or TBD oversees all four systems. A responsibility label does not add headcount. A person with several responsibilities counts once. Keep offsite management hours out of onsite totals. A personnel record does not require an app login.

Default weekly chart measure: peak concurrent onsite headcount, with installer and leadership series. It is not summed daily headcounts, unique visitors across a week, or FTE. Planned labor hours are the sum of headcount multiplied by scheduled block hours. Optional average equivalent staffing is onsite person-hours divided by that week's project calendar hours; label it explicitly and show not applicable for a zero-hour denominator.

Division peaks use aligned time blocks across active working plans, not the sum of independent weekly project peaks. Flag named-person conflicts across projects. Distinguish anonymous project demand from proof that employees are available. Show shortages against an optional entered availability limit; otherwise show availability not set. Exploratory scenarios do not enter the live division forecast.

Required numeric examples:
- Eight installers + PM + foreman, all five eight-hour days: peak 10, installer hours 320, leadership hours 80, total 400.
- Three dedicated installers and five shared: total installers remains eight.
- Eight installers and foreman all week, PM only Monday and Tuesday: peak 10, total hours 376, average equivalent staffing 9.4 over 40 hours.
- Eight installers, six ten-hour days: installer hours 480, peak installers eight.
- Two nonoverlapping eight-person eight-hour shifts: peak concurrent eight, daily person-hours 128. Do not label this as eight unique individuals for the whole day.
